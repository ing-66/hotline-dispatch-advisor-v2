# 热线派单系统 V2 成品交付与验收说明

## 交付结论

项目已形成统一启动、停止、健康检查和三档运行方式。推荐日常使用 `standalone`
档：SQLite 负责本地业务数据，Qdrant/Knowledge API 提供真实知识检索，配置的真实
LLM 负责研判；它不依赖当前机器未安装的 Docker/MySQL。

## 运行档位

| 档位 | 数据库 | 知识检索 | LLM | 用途 |
|---|---|---|---|---|
| standalone（默认） | 本地 SQLite | 真实 | 真实 | 本机正式使用 |
| production | MySQL 8.4 | 真实 | 真实 | 部署/既有 5,143 条历史工单 |
| demo | 本地 SQLite | Mock | Mock | 离线演示，不得用于实际派单 |

## 操作

```powershell
.\启动系统.ps1
.\scripts\health_check.ps1 -RequireKnowledge
.\停止系统.ps1
```

浏览器入口：<http://127.0.0.1:3000>。Business API 文档：
<http://127.0.0.1:8000/docs>。

## 验收标准

1. `start_all.ps1` 无错误结束，并输出 `Hotline V2 ready`。
2. 体检中 Business API + database、Frontend、Qdrant、Knowledge API 全部为 PASS。
3. 新建工单后能生成非 Mock 研判，页面展示建议首派单位、结论、置信度和引用。
4. 历史记录可重开，反馈可保存，案例可收藏和取消收藏。
5. `stop_all.ps1` 后 3000、8000、8088、6333 不再由本项目监听。

## 已知边界

- 研判结果是辅助建议，正式派单前仍需人工复核。
- `standalone` 不读取 MySQL 中既有的 5,143 条业务工单，但真实知识库中的历史案例
  仍参与检索；需要查看原始历史工单详情时使用 `production`。
- `.env`、知识服务真实配置和 `V2-data` 都属于本机运行资产，不进入源码交付。
- Demo 档明确使用 Mock，输出只用于确认界面与业务流程，不代表真实研判能力。
